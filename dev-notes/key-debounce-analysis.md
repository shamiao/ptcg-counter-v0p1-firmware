## 一、问题的由来（提问原话）

> 在 20ms 的时间片下，我们有没有必要采用这本书的这个方案？（这本书的时间片是 10ms）

提问背景：用户提供该书 9.2.2 节的照片页（图 9-4 状态机）。当时本项目刚实现
`Buttons_Scan()` 三态按键状态机（见 [business-logic-log.md](business-logic-log.md)
步骤 6），单拍采样即触发，用户在确认是否需要补一层"第二拍确认"。

## 二、书中方案还原（图 9-4：10ms 采样周期，单键三态）

把单个按键看作一个系统，三个状态：

| 状态 | 含义 |
|------|------|
| 状态0 | 无按键（空闲） |
| 状态1 | 首次采到闭合——**消抖候选，不触发** |
| 状态2 | 确认触发完毕，等释放 |

状态机图（弧上标注 输入/输出；输入=按键电平，0=闭合 1=断开；输出=1 表示
触发一次按键事件）：

```
              ↻ 1/0（断开维持）
         +--------------+     0/0（首次闭合）    +--------------+
         |    状态0     | -------------------> |    状态1     |
         | （无按键）   | <------------------- |（消抖候选）   |
         +--------------+     1/0（干扰：丢弃）  +--------------+
               ^                                      |
               |                                      | 0/1（第二拍确认，★输出1）
               | 1/0（释放）                          v
               |                              +--------------+
               +------------------------------|    状态2     |
                                              | （等待释放）  |
                                              +--------------+
                                                 ↻ 0/0（闭合维持）
```

精确转移表（与上图一一对应）：

| 当前态 | 输入 | 次态 | 输出 | 书中标注 |
|--------|------|------|------|----------|
| 状态0 | 1 | 状态0 | 0 | 维持空闲 |
| 状态0 | 0 | 状态1 | 0 | 进入消抖 |
| 状态1 | 1 | 状态0 | 0 | **干扰**（视为毛刺，丢弃） |
| 状态1 | 0 | 状态2 | **1** | **确认**（第二拍仍闭合才触发） |
| 状态2 | 0 | 状态2 | 0 | 等待释放 |
| 状态2 | 1 | 状态0 | 0 | 释放回空闲 |

核心机制：**第二拍确认**——首个闭合样本不触发，下一拍（10ms 后）仍闭合才输出
按键事件。等效于要求触点**稳定闭合 10~20ms** 才被承认。状态1→状态0 的"干扰"
路径就是确认失败的出口：单拍假闭合（毛刺/抖动瞬态）在这里被丢弃。

## 三、本项目现状（20ms 采样周期，七键三态）

`buttons.c` 的 `Buttons_Scan()`（每 20ms 片调用一次）：

- S0 空闲 →（恰好 1 键）→ S1，**当拍即触发**（返回该键掩码）；
- 任意态 →（≥2 键同按）→ S2 拦截（书里没有这个维度，单键模型）；
- S1/S2 →（全松）→ S0。

消抖手段：**20ms 采样节拍本身**。一次采样只看瞬时快照，触点抖动短于一片就不可
能同时落进两个相邻采样点。

## 四、分析

**1. 书需要确认态的根本原因：它的周期（10ms）短于抖动窗口。**
典型触点抖动闭合 1~5ms、断开可到 ~10ms。10ms 采样下，首个"闭合"样本完全可能
是抖动期里的瞬态，必须再等一拍确认。而本项目 **20ms 周期已大于整个抖动窗口**：
第一拍采到闭合，触点必然已真实按住。书里靠确认态挣到的消抖强度（10~20ms 稳定
门槛），本项目靠周期免费获得——对抖动 <20ms 的键，**两者可靠性等价**。

**2. 真正的残余差别只有一项：单点采样毛刺（EMI）免疫力。**
书的方案里一拍假闭合不会触发（下一拍断开就走"干扰"路径丢弃）；本项目一拍假
闭合立即触发。但本项目该风险很小：手持电池设备、按键内外双上拉、无长线、采样
窗口仅 µs 级。真正的噪声源（触点抖动）已被 20ms 周期覆盖。

**3. 代价不对等。**
采用书方案 = 在 S0 与 S1 之间插一个候选态（3 态变 4 态），并与已有的 S2 多键
拦截重新对齐；触发延迟上限从 20ms 升到 40ms（仍低于人手感知阈值 50~100ms，
无感，但复杂度换不来可靠性提升）。

**4. 边界条件不受影响。**
20ms 远小于人手最快敲击的闭合期（~100ms 起，≥5 个采样点），不会丢按键——书里
10ms 周期的这条论证对 20ms 同样成立。

## 五、结论与启用判据

**默认不采用。** 20ms 片下书中方案解决的主要问题（采样周期短于抖动窗口）在
本项目不存在；其附带收益（单点毛刺免疫）在本硬件上风险可忽略。

**启用判据**（满足任一即在 S0/S1 间插入候选态，改动局部、半天工作量）：

1. 台架出现**"没按却触发"**（`key N` 无对应操作）→ EMI 毛刺，确认态可滤除；
2. 台架出现**"一次按、触发两次"**（同键连续两条 `key N`）→ 坏开关抖动 >20ms，
   确认态 + 换键。

**依赖关系备忘**：若将来片长从 20ms 改回 10ms（或更短），书的前提重新成立，
确认态从"可选"变"必须"——改片长时必须连带评估此项。
